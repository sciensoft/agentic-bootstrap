# Request

Hardcode variant B as the picked value for the landing-page hero A/B/C test. Keep the random engine intact — don't destroy it. This is "for now."

## Reasoning

The repositioning shipped in `7a247eb` introduced a three-arm hero test (A: provocation, B: recognition, C: reframe) weighted 50/25/25. The owner wants to ship B as the canonical hero first while baseline conversion data is gathered in isolation — direct, organic, and social traffic all see identical copy during the initial post-repositioning window, so the signal can be compared cleanly to the pre-positioning history without a multi-arm split confounding it. Lifting the force later resumes the weighted random split.

The constraint "don't destroy the random engine" rules out deleting `pickWeighted()` or the localStorage paths. The chosen pattern: a top-of-IIFE `FORCE_VARIANT` constant that, when set to `'A'`, `'B'`, or `'C'`, short-circuits the variant computation **before** the localStorage read and write paths run. This way:

- The random engine, the bot-pinning branch, and the localStorage stickiness branch all stay defined and code-reachable.
- The force path bypasses `localStorage.setItem`, so previously-stored variants are preserved untouched. When the force lifts, returning visitors with a stored A or C keep it; new visitors get a fresh weighted roll.
- Lifting the override is one line: `FORCE_VARIANT = null;`.

## Output

- `docs/index.html` — `FORCE_VARIANT = 'B'` constant added to the head's variant-selection IIFE; new branch in the if/else chain checks the force before localStorage / random / bot logic. Random engine (`pickWeighted`), bot pinning, and localStorage stickiness left untouched. Also picked up two IDE-suggested modernisations in the same block (optional catch binding for the localStorage-get try, `.dataset.heroVariant` instead of `setAttribute`).
- `.docs/adrs/0009-reposition-as-engineering-memory-system-with-ab-test.md` — Consequences updated with a paragraph explaining the temporary force: rationale, what it bypasses (localStorage read+write), what it preserves (random engine, bot path, stickiness), revisit-when trigger (~500+ `experiment_view` events with `cta_*` attribution, or sooner if traffic invalidates the design), and how to lift (`FORCE_VARIANT = null;`).

Security rubric: no surfaces affected by this change (no auth, input validation, SQL, output encoding, transport, secrets, logging additions beyond the existing event payload, rate limits, dependency hygiene, or LLM context).
