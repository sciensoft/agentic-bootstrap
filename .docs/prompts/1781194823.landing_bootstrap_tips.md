## Reasoning

Two distinct failure modes a landing-page visitor needs to know about before they paste the prompt:

1. **Stalls / mid-bootstrap stops happen.** Even capable agents occasionally hiccup — context boundaries, edit-format quirks, network hiccups, weird local model behaviour. The bootstrap is designed to be idempotent precisely so a re-run picks up where it left off; the user just needs to know that's true and not assume they broke something.
2. **The playbook needs a capable model.** It's an 80-template multi-step orchestration that fits ~25k tokens of context for a smart agent and ~75k for a naive one. Small distilled reasoning models (R1-style, 14B-ish parameters) can't reliably hold the plan and tend to hallucinate a shortened version. Honest framing prevents the *"the bootstrap is broken"* misdiagnosis when it's actually a model-floor issue.

Tone choices:

- The re-run note is **6 words** at the user's explicit request — they pushed back on a longer first draft as too big for the tiny card footer. The 5-icon-grid pattern (refresh arrow + sentence) carries the meaning in minimum visual real estate.
- The capable-models advisory **names specific model families** rather than vague *"use a big model."* Concrete > vague even if it carries a small staleness risk (next-gen Claude / GPT will need a copy bump).
- The phrasing *"may skip steps"* mirrors the actual observed failure rather than implying weak models are categorically broken. The DeepSeek-R1:14B session literally skipped Steps 0–3 — accurate, not condescending.
