# Request

Four edits in the same commit:

1. Between the 3-step scaffold cards in the *60-second demo* section ([`docs/index.html`](../../docs/index.html)) and the *"Nudge it if it stalls"* helper below it, add a small centered beat that hands the reader back to their normal human-AI product-building loop. Explicit constraint: **not a 4th step**. The setup ends at Step 3; the beat says *"now go build."*
2. In the *Runtime footprint* section's lede, swap *"Your team never pays the playbook's token cost on a working session."* → *"The playbook's cost is paid at bootstrap. Regular sessions stay lightweight."* The new phrasing is affirmative and split into two short sentences; the old *"never pays"* framing was structurally a negation, and the *"working session"* qualifier read as jargon.
3. In the *Runtime footprint* section's third card (*Every session after*), swap the headline number *~10k tokens* → *~5–15k tokens*. The single-figure display over-committed to a specific runtime cost; a range acknowledges that the actual per-session number varies with the substrate scope the reader picks (which rule files load, which skills fire, which prompt-history spans are consulted).
4. In the same card, rewrite the description paragraph to: *"Agents usually auto-load only the thin spine — AGENTS.md plus the relevant rule files under `.agents/rules/`. The footprint depends on the gates you enabled and the assistant's loading strategy, but it stays far smaller than the original bootstrap playbook."* The prior copy (*"Tools auto-load … Scales modestly with the feature gates you opted into. Same on every agent."*) said *"tools"* where the actor is really the agent, hedged *"a few"* rule files where the truer scope is *"the relevant"*, and closed with *"Same on every agent."* which the *"assistant's loading strategy"* clause now handles more honestly — different agents load differently, and the copy should acknowledge that instead of flattening it.

## Reasoning

Currently the demo section closes with:

1. Card 01 — *Drop the file*
2. Card 02 — *Tell the agent*
3. Card 03 — *Get the scaffold*
4. *Nudge it if it stalls* (troubleshooting helper for low-capability models)

The reader who successfully runs the three steps gets a scaffold and then… sees a troubleshooting helper. No beat that says *"and now you build your product."* The section reads as if the bootstrap IS the destination, when in fact the bootstrap is the setup for what comes next — the reader's normal architecture / feature / refactor conversation with their agent.

A tiny bridge between the cards and the Nudge helper closes this gap without turning it into another step-numbered card (which would suggest *"there's more setup"* — the opposite of the intent).

## Design choices

- **Centered, not left-aligned.** The 3-card grid above and the Nudge helper below both have centered horizontal layouts (grid across full width, Nudge in a narrow `max-w-xl mx-auto`). A left-aligned bridge here would fight the surrounding rhythm. Centered reads as a beat between two centered blocks.
- **`max-w-2xl` container, not full-width.** Narrower than the 3-card grid above so the beat feels *quieter* — the eye is not carried edge-to-edge, it lands in the middle, reads the sentence, and moves on.
- **Single sentence, not two.** Attempted a two-sentence variant (*"That's the setup. Now go build."* + follow-up sentence) but the beat's job is to close a loop, not open a new thought — one sentence is enough.
- **`remembers` gradient, not `you already do` or `repository`.** *Remembers* is the load-bearing verb that names what the substrate provides. Gradient on `you already do` would over-emphasise the reader; gradient on `repository` would over-emphasise the mechanism. `Remembers` is the value.

## Runtime-footprint card description rewrite

- **[`docs/index.html`](../../docs/index.html)** at lines 917–920 — the *Every session after* card's body paragraph rewritten:
  - Before: *"Tools auto-load only the thin spine — AGENTS.md + a few rule files under `.agents/rules/`. Scales modestly with the feature gates you opted into. Same on every agent."*
  - After: *"Agents usually auto-load only the thin spine — AGENTS.md plus the relevant rule files under `.agents/rules/`. The footprint depends on the gates you enabled and the assistant's loading strategy, but it stays far smaller than the original bootstrap playbook."*
- Rationale: *tools* → *agents* names the actor honestly (it's the assistant deciding what to load, not the tools). *a few rule files* → *the relevant rule files* is more accurate — some assistants load more, some less. *"Same on every agent."* was aspirational; the new *"depends on the gates you enabled and the assistant's loading strategy"* clause acknowledges the reality without giving up the *"far smaller than the original bootstrap playbook"* payoff. `AGENTS.md` and `.agents/rules/` keep their `font-mono text-zinc-300` treatment (matching the surrounding pattern).
