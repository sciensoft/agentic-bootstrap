# Request

We're missing lots of the improvement points from the two positioning reviews; the additive approach is making the landing page harder to read, not easier. Capture the full backlog of improvements as a tracked artifact, and propose an approach — what gets restructured, what gets removed, what gets reframed in place — rather than continuing to bolt new sections on top.

## Reasoning

The hero is now repositioned (commits `7a247eb`, `9f5af86`), but the reviewers' deeper structural points still apply to the rest of the page: it leads with mechanism, lists artifacts before justifying them, reads as "an AI tool" rather than "an engineering practice." Continuing to *add* new content on top compounds the readability problem — the page is already too long. The right move is restructuring: reorder so value comes before mechanism, reframe artifact-listing sections to be outcome-first (mirroring the README change), cut sections that duplicate the README, and add the two genuinely-missing pieces (a workflow vignette and a comparison-vs-other-tools section). The owner flagged the missing capture explicitly — without a tracked artifact listing what's done vs open vs blocked, the backlog only lives in this conversation, which doesn't survive a context reset.

## Output

- **`.docs/todos/landing-positioning-restructure.md`** — the working backlog for the multi-commit restructure. Contains:
  - **Improvement inventory** — 15-row table covering everything from the two reviewer PDFs + the user's intuitions, with status markers (✅ done · 🟡 partial · ⬜ open · ❓ blocked).
  - **Proposed restructured outline** — the value-first section order (Hero → Problem → Substrate → Vignette → How it works → Architectures+Postures → Comparison → Adoption).

The form bends the usual one-file-per-deferred-idea TODO convention because this initiative IS one idea with many sub-items; splitting would lose the dependency graph between phases. Acknowledged in the file's Deferred-because section.

No code changes to `docs/index.html` or other surfaces — this commit captures the plan only. Phase 2 (reorder existing sections) is the next concrete edit and will be its own commit.
