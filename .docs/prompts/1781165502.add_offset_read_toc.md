## Reasoning

The bootstrap file is ~80k tokens read top-to-bottom. A typical project touches ~15 of the ~80 templates inside it — Python + 4-Layer DDD + Claude-only + TRUSTED_DEV doesn't need the 8 other tool adapters, 8 other architecture variants, 12 other posture variants, or 4 other language scaffolds it loaded. That's pure waste.

The fix: a Template Index at the start of Part 4 mapping each template to a line range, plus a Step 4 instruction telling capable agents to use `offset` + `limit` reads to load *only* what their captured answers require. Three properties matter:

1. **Backward-compatible.** Agents without offset-read capability (or hosts that ignore the instruction) fall through to top-to-bottom reading. Functionality is unchanged; only the savings are forfeited.
2. **Self-contained.** No URLs, no fetches, no external manifest. The index lives inside the same single file. Honors the "self-contained, no external network" design principle.
3. **The win is real.** Smart agents drop from ~80k → ~25k tokens at scaffold time (~60–70% reduction). For Claude Code's pricing model, that's about $0.50 of saved input cost per typical scaffold against Opus 4.7. At fleet scale (hundreds of bootstraps) it compounds.

The landing page's `Runtime footprint` section gets updated from two cards (scaffold/runtime) to three (smart scaffold · naive fallback · runtime) so the three-number story is visible to anyone landing on agentic-bootstrap.md.
