# Request

> Let's continue to step "2. Three repo files to add (none exist today)"

(Referring to a multi-step plan for accepting external contributions: branch-protection ruleset → repo files → general settings → Discussions → Issues. Step 2 = the file-based community infrastructure that was entirely missing.)

## Reasoning

The repo had `lint-bootstrap.yml` and no other GitHub-community files when the LinkedIn launch went live. Contributor-readiness was the next gap. Two specific shapes mattered:

1. **A dedicated tool-churn issue template** — tied to the maintenance-treadmill mitigation in [ADR-0004](../adrs/0004-single-file-agent-executable-delivery-model.md). The eight supported tools can change their settings schemas independently; a vague *"Cursor is broken"* report becomes a question-asking loop, but a structured churn report (tool / version / before / after / source) is PR-ready input.
2. **A `config.yml` that routes general questions to Discussions** — keeps the issue tracker tight by separating bug-tracking from conversation.

The full design lives at [ADR-0007](../adrs/0007-structured-contribution-intake.md).
