# Request

Reposition the project as an engineering-memory system on the static surfaces (README, landing-page meta, OG tags) using a hybrid of the three candidate framings — and run an A/B/C test on the landing-page hero across the three positioning options so visitor behaviour picks the winner. Pick variants with weighted random (bias toward B, the recognition-led variant), stick the choice per-visitor via `localStorage`, instrument variant assignment + downstream conversions through the existing `gtag.js`, and preserve the old landing page as `docs/index.v1.html` for rollback.

## Reasoning

Two independent reviewers converged on the same diagnosis: the project's surfaces lead with **mechanism** ("one markdown file, any agent, one prompt") rather than the **problem** it solves, and read as "another bootstrapper" before the visitor reaches the substance. Both reframed the bootstrap's substrate — `AGENTS.md`, `.agents/rules/`, `.docs/adrs/`, `.docs/prompts/`, `.docs/todos/`, `.docs/security/methodology.md` — as collectively an **engineering memory system**: episodic memory (prompts), semantic memory (ADRs), working memory (TODOs), procedural memory (rules), evaluative memory (security rubric). The repo *becomes* the memory; agents are consumers of it.

We didn't want to bet the whole positioning blind on one variant — "engineering memory" is unproven copy and the three candidate framings (provocation, recognition, reframe) test different psychological gestures, not just different words. So static surfaces (README, meta, OG) pivot to a hybrid that combines the strongest pieces (descriptive tagline + recognition aha quote + problem→substrate→solution prose + outcome-first table), and the landing-page hero runs a three-arm A/B/C test instrumented via the gtag snippet that's already on the page. Variant B is favored 50/25/25 because its every line is a true statement about the world, so a bounce on B has the smallest copy-credibility cost; A and C still get enough exposure to compare.

## Output

- `docs/index.v1.html` — verbatim snapshot of the pre-repositioning landing page (rollback path).
- `docs/index.html` — new landing page:
  - `<title>`, `<meta description>`, `og:title`, `og:description` rewritten to the memory framing (B-aligned, since crawlers see one variant).
  - Inline `<head>` script picks variant from `localStorage`, else weighted random (50% B / 25% A / 25% C); pins bots to B; sets `<html data-hero-variant="X">`; pushes `experiment_view` with `{ experiment_id, variant }` through `gtag`.
  - CSS attribute selectors hide non-matching variant blocks — no flash of wrong content.
  - Three sibling hero blocks (`data-hero-variant-block="A|B|C"`) for the eyebrow + H1 + lede; CTAs and Works-with strip stay shared.
  - `data-ab-event="cta_get_bootstrap"` / `cta_github` on the two hero CTAs.
  - `data-hero-end` on the post-hero section as the scroll observer's target.
  - End-of-body script attributing CTA clicks, `scroll_past_hero` (IntersectionObserver), and `engaged_30s` (setTimeout) to the active variant.
- `README.md` — hybrid lede (descriptive tagline + recognition aha quote + 3-paragraph problem→substrate→solution block); reframed "What lands in your repo" table to **outcome-first** with the header changed from *Habit* to *What the repo gains*.
- `.docs/adrs/0009-reposition-as-engineering-memory-system-with-ab-test.md` — captures the positioning thesis, the three variants, the weighted-random mechanism, the gtag events, and the consequences (incl. the GA4 admin step). Index updated.
- `.docs/todos/register-ga4-custom-dimensions-for-ab-test.md` — admin-side follow-up to register `experiment_id` and `variant` as Event-scoped custom dimensions in GA4 so the dashboard can segment by variant.

Telemetry: experiment_view + cta_get_bootstrap + cta_github + scroll_past_hero + engaged_30s, each parameterised with `experiment_id="hero_2026_q3"` and `variant="A|B|C"`. No PII or sensitive data in payloads.

Security rubric (per `.agents/rules/workflow-security.md`): walked **§Logging** (no sensitive data — events carry only experiment ID + variant; localStorage key is non-identifying); walked **§Input validation** (no user input — `Math.random()` for variant, hard-coded enum check on read); walked **§Dependency hygiene** (no new deps — uses existing `gtag.js` already on page). No changes to auth / SQL / output encoding / transport / secrets / rate limiting / LLM context.
