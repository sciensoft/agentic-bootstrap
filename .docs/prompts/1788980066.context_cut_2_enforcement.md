## Reasoning

Cut 1's design turned the always-loaded rule set into a trigger index, but §6.5 of the improvements doc flags the load-bearing risk: the index only works if the right rule fires unprompted when its condition fires. Section 9 addresses that risk with two layers:

- **Universal, agent-agnostic** — post-facto, works on every host: `make rules-check` audits the index (orphans, broken links, budget); a pre-commit hook cross-checks staged paths against the index (via a per-project script whose case ladder is generated from interview flags) by requiring the committed prompt file to name every rule its paths fire.
- **Per-host reinforcement** — pre-facto, opt-in on `CLAUDE ∈ AGENTS_USED` / `CURSOR ∈ AGENTS_USED`: Claude's `PreToolUse` hook fires *before* the edit and injects a one-line reminder naming the rule to open, deduped once per session; Cursor's `alwaysApply` rule injects the compact trigger index on every message via Cursor's own rule loader.

Hosts without hook infrastructure (Aider / Codex / Continue / Windsurf / Copilot) get the universal layer plus the always-loaded rule text — graceful degradation, not a gap.
