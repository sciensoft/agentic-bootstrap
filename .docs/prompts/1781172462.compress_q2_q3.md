# Request

> Ship them!

(In response to a proposal — *Category B, passes #2 + #3* — to compress Q3 (POSTURE, 1,537 chars) and Q2 (AGENTS_USED, 945 chars) using the same shape Q5 just got: a short question + a dedicated sub-table. Lessons from the Q5 cycle applied: trust modern chat agents to render markdown tables; don't over-engineer the question text with a redundant inline list.)

## Reasoning

Q3 and Q2 had the same structural problem Q5 had — a single cell glued multiple option descriptions together with semicolons, producing a wall of text that was hard for the user to skim and forced the agent to load a large prose blob just to ask one question. The compression pattern proven on Q5 applies cleanly to both.

Two specific wins beyond the obvious readability gain:

1. **Q2's `AGENTS.md natively?` column.** The old paragraph noted "OpenAI Codex CLI (reads `AGENTS.md` natively — no extra file); OpenCode (reads `AGENTS.md` natively — no extra file)" mid-paragraph. Two of the eight supported tools need no adapter file at all, and a user picking tools might choose those because there's nothing to maintain. The column surfaces that pattern at a glance.
2. **Q3's `TRUSTED_DEV` cross-reference moved to a footnote.** The current row described `TRUSTED_DEV` as *"read-only + safe git workflow + language-specific build / test commands (`uv:*` / `npm:*` / `go:*` / `cargo:*` picked from Q4 `LANG`)"* — the cross-reference to Q4 was the densest sub-clause in the entire interview. Moving it to a one-line footnote under the sub-table makes both the `TRUSTED_DEV` row and the cross-ref easier to read.
