# Request

> So, we have lots of issues fiting the bootstrap into memory, so other users might have the same if they assume they could use smaller models. We should somehow highlight the limitations of it. What do you think?

(Refined across the conversation to be **runtime-agnostic** — the user pushed back on Aider-specific framing because Continue.dev, Cursor chat, and other always-attach agents hit the same wall; then asked to scope only to the user-facing surfaces because *"a model that hits the warning has already passed the test; a model that fails never reads the warning."*)

## Reasoning

Real debug session generated the symptom: 2× RTX 3090 (48 GB VRAM combined), Qwen 2.5 Coder 32B built with a custom Modelfile carrying `PARAMETER num_ctx 131072`, still loaded by Ollama at 32k because the GGUF metadata caps at 32k regardless of what the Modelfile asks for. Aider sent 81k tokens; Ollama silently dropped the first ~49k (the file content); the model accurately reported *"please provide the contents of `AGENTIC-BOOTSTRAP.md`"*.

The visitor needs to know **before** running the command that the bootstrap requires a window most local-model defaults don't provide. Three angles to surface:

1. **Model architectural cap** — many models on Ollama (whole Qwen 2.5 family, Codestral, Phi-4) are GGUF-capped at 32k regardless of what Modelfile parameters request.
2. **Runtime cap** — even when a model architecturally supports more, Ollama/vLLM/llama.cpp ship with their own defaults that further clip; the user has to verify *both*.
3. **Agent dispatch shape** — Aider-style "send the whole attached file every turn" agents bottleneck on the model's context; Claude Code / Cursor / Continue (tool-mode) use chunked reads that don't.

The escape hatch: hosted API. The bootstrap is one-shot — $0.50 of Sonnet input is rounding error against any dev day, and the user can run their local model for everything else.

Why no bootstrap-internal warning: a model that has enough context to read the *Before you start* section has already passed the test; a model that doesn't never reads the section at all. The warning would be paradoxical inside the file. The user spotted this and we agreed to drop that pass.

Why README in addition to landing page: a fraction of first-time visitors arrive via the GitHub repo (search, direct link, ecosystem post) and never see the landing page. The README's Quick start currently shows the curl + the prompt but no context-budget caveat — the same trap.
