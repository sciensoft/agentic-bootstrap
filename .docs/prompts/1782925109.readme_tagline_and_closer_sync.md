The README's callout and closer were both stale relative to the landing page: the callout still used the *"AI sessions end. Engineering knowledge shouldn't."* framing that ADR-0010 superseded, and the closer landed on *"day-one discipline"* which was the ADR-0009-era hero language.

A targeted quick-sync of just the callout + closer stops the highest-visibility staleness (the two surfaces a first-time visitor sees first and last) without committing to the full pivot, which needs its own careful drafting on the intro paragraphs.

### Callout new copy — tagline preservation

The two-sentence pair *"The best engineering now happens in conversation. It shouldn't disappear with it."* is captured verbatim from the landing page's Aha section H2. Per the tagline-preservation feedback memory, this sentence pair must stay verbatim through iterations — the line break between them is load-bearing pacing. In Markdown callout form, that's rendered as two paragraph-separated blockquote lines:

```markdown
> **The best engineering now happens in conversation.**
>
> **It shouldn't disappear with it.**
```

The blank blockquote line between them forces a paragraph break so the two sentences render as visually separated beats, matching the H2's two-block treatment on the landing page.

### Closer new copy — "a repository that remembers"

*"A repository that remembers"* echoes the demo handoff beat added in `feat/demo-keep-going-beat` (still pending PR): *"That's the setup. From here, it's you and your agent doing what you already do — with a repository that remembers."* Reusing that phrasing keeps the README consistent with the landing's current voice without pulling in origin-story-specific content the user explicitly scoped out.

*"Behind every conversation"* is added because *"remembers"* alone is too abstract for a closer — the reader needs to hear *what* the repository remembers. *"The engineering behind every conversation"* names it: the architecture, decisions, trade-offs, and future ideas the conversation produces.
