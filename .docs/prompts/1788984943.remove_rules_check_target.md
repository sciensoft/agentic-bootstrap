# Request

Remove the `rules-check` Makefile target from all 5 emitted Makefile variants in `AGENTIC-BOOTSTRAP.md`, from this repo's own Makefile, and trim the mention from the `[2026-09-09]` CHANGELOG entry's Cut 2 bullet.

## Reasoning

The user's critique lands: `make rules-check` is emitted into every bootstrapped project but nobody reaches for arbitrary Makefile targets they didn't specifically wire up. The compliance check that users *do* invoke in practice is the bootstrap file's **doctor mode** (`"bootstrap-doctor"` in Step 0), which walks a broader set of drift checks (sentinels, adapter coverage, ADR index, todo hygiene, refinement status). `rules-check` and doctor mode overlap; doctor mode is the one users actually reach for. Meddling with users' Makefiles for a target that will sit unused is a net-negative UX trade — we're adding surface area to a file users maintain, in exchange for a check that has no invocation path.

Not touching:
- `.pre-commit-config.yaml`'s `local` hook and `scripts/check_consulted_rules.sh` — pre-commit projects invoke the hook automatically on commit, so it pays off unlike `rules-check`.
- The Claude `PreToolUse` hook and Cursor `alwaysApply` trigger-index rule — those fire automatically, no manual `make` invocation needed.
- Doctor mode itself — that stays as the compliance path.

Trade-off accepted: the specific orphaned-rule / broken-link / byte-budget checks that `rules-check` did are simply gone. If we want them back later, folding into doctor mode or `scripts/lint_bootstrap.py` (this repo's Sacred lint) is one grep away. Skipping that now to keep this cut focused.
