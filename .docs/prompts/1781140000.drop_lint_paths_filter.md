# Request

> Take the easiest path then!

(In response to a diagnosis: after the `develop` ruleset added `lint` as a required status check, the CI workflow's `paths:` filter created a deadlock — PRs touching files outside the filter wouldn't trigger the workflow, but the required check would wait indefinitely. Two fixes were on the table: drop the `paths:` filter so the lint runs unconditionally, or add a tiny always-runs "satisfy the check" job. The user picked the simpler one.)

## Reasoning

The lint takes ~3 seconds; running it on every PR has negligible cost. The alternative — a parallel always-runs job that reports success when the real lint is skipped — was rejected as cleverness without payoff (more config, more confusion). The full decision sits at [ADR-0002](../adrs/0002-drop-paths-filter-from-required-lint-check.md).

## Output

- [`.github/workflows/lint-bootstrap.yml`](../../.github/workflows/lint-bootstrap.yml): removed the `paths:` filter from both the `pull_request:` and the `push:` triggers. Workflow now runs on every PR and every push to `main` / `develop`.
- Header comment updated to document *why* the filter is absent so it doesn't get re-added by reflex.
