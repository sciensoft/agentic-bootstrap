# Request

Adjust the R1 hero on four points:

1. The eyebrow *"An engineering operating model for human–AI software development"* is too abstract — simplify it.
2. The H1 *"Software engineering changed."* should staircase word-by-word: *Software / engineering / changed.* (each word on its own line) before *Repositories haven't.*
3. The bootstrap quality of the project is missing — *"AGENTIC_BOOTSTRAP makes it durable"* names the noun but not the action. Bring it back into the hero.
4. The right-column terminal codeblock visual (the bootstrap interview Q&A + scaffold file tree) must stay beside the hero — non-negotiable.

Also: bring back the pre-positioning subhead — *"One markdown file. Any agentic coding assistant. One prompt. Your repo grows the discipline a Senior Engineer would have set up on day one — workflow rules, ADR culture, the testing pyramid, telemetry, security rubric, TODO discipline — then bundles every change into one focused git commit. Tool-agnostic. Cross-stack. Idempotent."* — with adjustment for the new framing.

## Reasoning

The R1 commit (`96864c7`) shipped a hero aligned with the brief's strictest reading: curiosity only, no mechanism, no implementation visual. User testing — *"I feel it's very difficult to understand"*, *"missing the bootstrap quality"*, *"the terminal screenshot is non-negotiable"* — exposes the cost of that strict reading. The brief was right about leading with the category shift, but wrong (or at least over-applied) about scrubbing the project's identity-level affordances from the hero. The terminal codeblock isn't *"AGENTS.md, ADRs, TODOs"* (the brief's explicit "never lead with" list); it's a visual demonstration of the **bootstrap act itself** — drop the file, run your agent, scaffold lands. That's the project's identity, not its mechanism, and stripping it makes the hero land as philosophy with no observable affordance.

The eyebrow *"An engineering operating model for human–AI software development"* is the brief's exact positioning phrase — but on a landing surface where first-read clarity matters more than positioning precision, the longer "operating model for human–AI software development" reads as consulting-speak and slows comprehension. The simpler *"An engineering memory system for AI-coded repos"* (the exact eyebrow from the pinned-to-B variant under ADR-0009, which the user had already approved) keeps the core meaning, gets read in one beat, and lands the audience signal (*AI-coded repos*) without abstraction. The longer positioning phrase survives in the ADRs and README where context lets it breathe.

The H1 staircase — each word on its own line for the *"Software / engineering / changed."* fragment — mirrors the previous variant B's 3-line gradient pacing. Stacking on word boundaries creates dramatic rhythm; the gradient on *"Repositories haven't."* (line 4) becomes the punchline that opens the curiosity gap.

The subhead solves the bootstrap-quality gap in a single block. The pre-positioning version named the bootstrap action well — *"One markdown file. Any agentic coding assistant. One prompt"* is unbeatable as an opening triad. The only adjustment needed under the new positioning is swapping *"discipline"* → *"engineering memory"* in the long sentence's noun, so the subhead sits inside the new noun phrase. Everything else — the artifact list, the *"focused git commit"* habit, the closing *"Tool-agnostic. Cross-stack. Idempotent."* triad — survives unchanged because it's still true and still the right concrete-after-philosophy bridge.

The trade-off: the hero is now **hybrid** rather than strictly curiosity-only. The brief argued for a curiosity-only hero; this commit accepts a slightly less pure hero in exchange for keeping what the project actually IS visible above the fold. ADR-0010 already had to soften — this revision makes that softening explicit and reasoned, not implicit.
