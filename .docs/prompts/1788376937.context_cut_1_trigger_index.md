# Request

Apply the improvements catalogued in `AGENTIC-B.Improvements.md` to `AGENTIC-BOOTSTRAP.md` so future bootstrap runs produce projects with the trimmed context. Three cuts, three PRs. This file covers **Cut 1**: adapters become stubs, `AGENTS.md` gains an `Always` block plus a trigger index that replaces the `## Rules` bullet list, and `workflow.md` is rewritten from per-request to per-task with a task-boundary rule agents can declare rather than infer.

## Reasoning

A generated repo currently loads ~47k tokens of rule material before the user types anything (see §1 of the improvements doc). ~100KB of the 135KB is reference-shaped — material to consult when a condition holds, not instructions that change what the agent does on an arbitrary turn. That crowds out the request itself and produces well-formed answers to questions the user did not ask.

The design (improvements doc §6) keeps every rule file where it is; it just stops preloading them. Per-agent adapters point at the agnostic `AGENTS.md`; `AGENTS.md` carries an `Always` block (four rules that apply every turn regardless of agent) plus a trigger index naming path → rule for the reference material. Reference is loaded when the trigger fires. Rows in the index stay in-context so the pointer is always seen even though the body is not.

The task-boundary rule solves the second complaint: agents were writing one prompt file per turn, spraying the directory on any refinement. The fix from the discussion is *declared* task boundaries, not inferred — the agent classifies each turn as continuing or new, with a commit as the default boundary and explicit user signals as override triggers. This is not currently in the improvements doc; it belongs in the `Always` block.

Cut 1 is self-contained and reversible — no rule file moves; each `@`-import becomes a trigger-index row.
