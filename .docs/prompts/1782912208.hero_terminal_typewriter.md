# Request

Animate the prompt-line inside the hero terminal illustration ([`docs/index.html`](../../docs/index.html)). The static prefix *"› follow AGENTIC_BOOTSTRAP.md and "* stays; the suffix cycles through five directive endings, typewriter-style, with a backspace-erase between each:

1. *let's engineer this together* (typed out on first paint)
2. *let's build this together*
3. *let's get started*
4. *let's engineer this together*
5. *let's do this right*

Then loops back to (1). Timing should let the reader actually catch each variant, not blur past.

## Reasoning

The terminal illustration in the hero's right column is identity-level per [ADR-0010](../adrs/0010-reposition-as-engineering-operating-model.md) (*"this is a thing you can run, and here is what running it looks like"*). Statically it reads once and fades. Animating the prompt line makes the visitor's eye return to it — and the five variants smuggle in a small piece of positioning that no static line can: *AGENTIC_BOOTSTRAP is language you use with the agent*, and the agent responds to a range of intents (*engineer this*, *build this*, *get started*, *do this right*). None of those endings are marketing claims — they're plausible things an engineer actually types. The animation makes the terminal feel *live* without adding chrome or content.

The variant list intentionally repeats *"let's engineer this together"* at position 4 to reinforce the primary framing (aligns with the H1's *engineering* emphasis) without making it the only phrase the reader sees. Positions 2, 3, 5 broaden the tonal range: *build* (concrete), *get started* (low-friction), *do this right* (discipline-forward).

## Output

- **[`docs/index.html`](../../docs/index.html)** — three surgical additions:
  1. **Markup** on the prompt-line `<div>` (was: `<div class="text-zinc-500 mt-1">› follow AGENTIC_BOOTSTRAP.md and let's engineer this together</div>`). Now: adds `.hero-prompt-line` class; wraps the changing suffix in `<span data-hero-typing>...</span>`; appends `<span class="hero-cursor" aria-hidden="true">▍</span>` for the blinking cursor. The initial DOM still contains the full first-variant text so the pre-JS/JS-off/bot render reads coherent.
  2. **CSS** appended to the existing `<style>` block: `.hero-prompt-line { min-height: 3.25em; }` reserves two lines of vertical space so shorter variants don't shift the Q&A block below; `.hero-cursor` blinks via `steps(2, start)` on a 1.05s cycle (hard on/off, not fade — terminal-authentic); `@media (prefers-reduced-motion: reduce)` disables the cursor blink. `min-height` sizing is `3.25em` on a `text-[13px]` `leading-relaxed` (line-height 1.625) parent — 2 * 1.625em = 3.25em = ~42px = two lines of the ambient prompt-line font-size.
  3. **JS** appended inside the existing bottom `<script>` block: an IIFE that (a) skips entirely under `prefers-reduced-motion`, rendering `variants[0]` statically so the sentence still reads complete; (b) types character-by-character at 55ms/char, holds the fully-typed line for 2.6s so the reader can read it, backspaces at 30ms/char, pauses 350ms as a *think* beat, then types the next; (c) loops through the five-entry array indefinitely; (d) fires 500ms after page load to let the hero settle first.
- **Prompt file** — this file.

## Notes

- **No ADR change.** This is an enhancement to the terminal codeblock ADR-0010 already documents keeping. It doesn't shift the ADR's core decision or introduce a new load-bearing pattern. If future changes materially expand the animation (e.g., animating the Q&A rows too, or making the variants A/B-testable), an ADR mini-update or a new ADR would be warranted then.
- **Accessibility.** The blinking cursor is `aria-hidden="true"` (screen readers should never announce `▍`). The typewriter span itself is not marked aria-hidden — screen readers navigating the terminal illustration will hear whichever variant is on screen at the moment they land on the node. That's the same experience as any dynamic content on a landing page; no special handling needed for a decorative terminal illustration.
- **Layout stability.** Reserving 3.25em prevents the Q&A block below from jumping. On very narrow viewports the prompt line may wrap earlier and the reservation may over-provision by ~one line's worth — acceptable trade to avoid the jitter.
- **Copy-button flow.** The terminal codeblock doesn't currently have a copy-button wired up (it's decorative, not a copy-target), so the typewriter and the copy-button flow don't interact.
