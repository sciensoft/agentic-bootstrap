# Request

Fix the hero terminal typewriter animation ([`docs/index.html`](../../docs/index.html)) so that the FIRST typing cycle types the whole line — *"follow AGENTIC_BOOTSTRAP.md and let's engineer this together"* — from empty, not just the *"let's engineer this together"* suffix. Subsequent cycles behave as before: only the suffix is backspaced and re-typed.

## Reasoning

The previous version ([prompt 1782912208](./1782912208.hero_terminal_typewriter.md)) kept *"follow AGENTIC_BOOTSTRAP.md and "* as static HTML text outside the animated span, so the JS only ever animated the suffix. The user's read of that: the first-time visitor never sees anyone typing the whole intent — they land on a half-static, half-cycling line. Emotionally weaker than watching a full command materialise.

The fix: move the entire line into the `data-hero-typing` span; JS starts at empty and types the full target the first time; subsequent erases stop at `prefix.length` (34 chars — *"follow AGENTIC_BOOTSTRAP.md and "*) so only the suffix rotates.

## Output

- **[`docs/index.html`](../../docs/index.html)** — two edits:
  1. **Markup**: the static prefix *"follow AGENTIC_BOOTSTRAP.md and "* moves from outside the span to inside. The prompt-line div now reads `› <span data-hero-typing>follow AGENTIC_BOOTSTRAP.md and let's engineer this together</span><span class="hero-cursor">▍</span>` — only the `› ` shell chevron stays as terminal chrome outside the animated span (that's not something a user types; it's the prompt itself).
  2. **JS**: the IIFE gains a `prefix` constant. `type()` now targets `prefix + variants[variantIdx]` instead of just `variants[variantIdx]`; `erase()` stops at `text.length > prefix.length` instead of `> 0`. The `charIdx` counter is dropped (redundant with `text.length`). Behaviour: first cycle types the full 62-char line from empty; every subsequent cycle types only the suffix (28 chars for the longest variant, 17 for the shortest) on top of the preserved prefix.

  Also updates the header comment and the `el.textContent = ''` inline comment to describe the new behaviour, and the `prefers-reduced-motion` branch now renders `prefix + variants[0]` (the whole line) rather than just the suffix — otherwise reduced-motion users would see an incomplete sentence.
