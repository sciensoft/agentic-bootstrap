# Request

Port the MCP-handling guidance from §7 of `AGENTIC-B.Improvements.md` into the generator. Ship the pieces the generator can actually control: a starter template with the safety pattern (pinned versions, named allowlist not blanket switch, denylist for account-level connectors) and a measurement note in the always-loaded brief pointing at the levers. Skip the interview question for MCP — the current `.claude/settings.json` templates already omit `enableAllProjectMcpServers: true`, which is the load-bearing safe behavior; a user who wants named allowlist entries can add them post-bootstrap.

## Reasoning

The improvements doc §7 itemises MCP payload as the second-largest line item after the conversation itself — up to 66k tokens in the measured session, 86% of which came from account-level claude.ai connectors the generator cannot touch. Only the project's own `.mcp.json` is under generator control, and even there most projects don't need MCP servers.

The load-bearing bit the generator can ship: (a) a starter template that encodes the safety pattern so users adopting MCP don't accidentally ship `@latest`-pinned commands or `enableAllProjectMcpServers: true`; (b) a note in the always-loaded brief pointing at the denylist lever for account-level connectors, since that's where users find the biggest wins. Not shipping a `.mcp.json` directly (users copy from `.example`) means the file's presence doesn't accidentally activate MCP on projects that don't need it.

An interview question ("does this project use MCP?") would be tidy but premature. Most projects don't need MCP; users who do will configure it themselves. Adding a Q now costs interview length for a small opt-in benefit.
