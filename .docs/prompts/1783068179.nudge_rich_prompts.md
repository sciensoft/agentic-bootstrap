# Request

Some UI-capable hosts (Claude Code VSCode extension, Continue.dev, IDE extensions with prompt primitives) start the AGENTIC_BOOTSTRAP.md questionnaire in plain text instead of using their rich interactive prompt UI (pickers, dropdowns, multi-select). Screenshot user shared: Claude Code's `AskUserQuestion` picker for Q2 — that's the shape the interview SHOULD land in when the host supports it.

Two edits landing together, per user directive *"do this first than we plan the next one below"*:

1. **Landing page** — add a companion nudge card next to the existing *"Nudge it if it stalls"*, so the user can paste a short prompt when the picker UI doesn't show up on first read.
2. **AGENTIC-BOOTSTRAP.md Step 2** — strengthen the internal rich-picker directive from *"use it"* to *"you MUST use it"*, name the failure mode explicitly, and pre-register the paste-nudge phrase so the agent knows to switch mid-interview when it sees it. This is the higher-impact fix; the landing nudge is the fallback.

Goal named by the user: *"avoid getting the user to nudge much, but make it clear that nudging is sometimes needed."*

## Reasoning

The bootstrap already had a rich-picker directive at [`AGENTIC-BOOTSTRAP.md:160`](../../AGENTIC-BOOTSTRAP.md) (*"If your host supports a structured interactive question tool ... use it — one tool call per question."*). In practice, that softer *"use it"* wasn't reliably landing. The three edits combine into a two-layer defense:

- **Prevent the miss:** strengthen the directive so agents that read the file carefully don't fall back to plain text.
- **Escape hatch when the miss happens anyway:** a paste-line the user can drop into the chat to switch the agent mid-interview.
