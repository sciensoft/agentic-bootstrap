# Request

Change the hero terminal typewriter ([`docs/index.html`](../../docs/index.html)) from "shared-prefix + swappable suffix" to five fully distinct command sentences, typed and erased in full each cycle. The variants in order:

1. `follow AGENTIC_BOOTSTRAP.md and let's build this together`
2. `bootstrap this repository using AGENTIC_BOOTSTRAP.md`
3. `before we start, follow AGENTIC_BOOTSTRAP.md`
4. `initialize this repository with AGENTIC_BOOTSTRAP.md`
5. `use AGENTIC_BOOTSTRAP.md as the operating model for this repository`

## Reasoning

The previous version ([prompt 1782912590](./1782912590.hero_typewriter_type_whole_line_first.md)) shared a *"follow AGENTIC_BOOTSTRAP.md and "* prefix across all cycles — after the first cycle only the suffix rotated. That made every subsequent variant read as a slight variation on the same phrasing (*"and let's engineer"*, *"and let's build"*, *"and let's get started"*), which reads more like slogan A/B testing than the range of ways engineers actually address their agent.

The new set demonstrates that range explicitly: an imperative *"follow ... and let's build"*, an active *"bootstrap this repository using ..."*, a preparatory *"before we start, follow ..."*, an initialise-verb *"initialize this repository with ..."*, and a positioning-forward *"use ... as the operating model for this repository"* that echoes ADR-0010's *engineering operating model* framing. Each variant reads as something a different engineer might realistically type — collectively they smuggle in the positioning without any of them announcing it.

## Output

- **[`docs/index.html`](../../docs/index.html)** — two edits, one in the markup and one in the JS:
  1. **Markup**: seed inside `<span data-hero-typing>` updated from *"follow AGENTIC_BOOTSTRAP.md and let's engineer this together"* → *"follow AGENTIC_BOOTSTRAP.md and let's build this together"* (matches the new `variants[0]` so pre-JS / bot / no-JS state reads coherent).
  2. **JS**: the `prefix` constant is removed. `variants` is replaced with the five full sentences. `erase()` goes back to `text.length > 0` (full erase each cycle, not down to `prefix.length`). `prefers-reduced-motion` branch now renders `variants[0]` (already a full sentence) instead of `prefix + variants[0]`. Header comment rewritten to describe the new positioning-through-variance behaviour.
- **Prompt file** — this file.

## Layout notes

The longest new variant is `use AGENTIC_BOOTSTRAP.md as the operating model for this repository` at 66 characters. Combined with the `› ` chevron and the blinking cursor, the full rendered line is ~68 characters. At the terminal panel's typical monospace width (~60 chars per line inside `lg:col-span-5` with `p-5`), this should wrap to two lines — the same as the previous longest variant. The existing `.hero-prompt-line { min-height: 3.25em; }` reservation (2 lines at `leading-relaxed` 1.625) still covers this without additional layout work. If v5 spills to three lines on narrower breakpoints and causes visible jitter, follow-up: bump the reservation to `4.875em` (3 lines).

## Timing

Kept unchanged: 55ms/char type, 30ms/char erase, 2600ms hold, 350ms think. With the longer variants a full cycle for v5 now takes ~8.5s (type ~3.6s + hold 2.6s + erase 2.0s + think 0.4s); the shortest cycle (v3) takes ~5.6s. Total loop through all five ≈ 35–40s. That's a lot per loop but the target is first-fold impression — visitors typically see one to two variants before scrolling, and returning-gaze visitors get more surface area with the longer loop.
