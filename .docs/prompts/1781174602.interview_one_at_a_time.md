# Request

> Also, when using Aider, it printed the whole list in one go. After answering Q1, I got all the remaining questions printed again. I had to eventually ask it to ask one by one ("Ask one question at time please!") as you can see at the end and it provided a better experience. So how can we ensure we get it from the start without me having to ask for it? Maybe other less modern AI agents will have the same problem, so ensuring one by one is very important for readability and usability.

(Real Aider session transcript attached to the request showed the failure: agent listed all 17 questions in one message, then *again* after Q1 was answered. User had to manually type *"ask one question at a time please!"* to recover the interview-style flow.)

## Reasoning

The previous Step 2 instruction said *"otherwise ask one question at a time in chat"* — buried at the tail of a single paragraph, easy for a chat-only agent to miss when scanning the playbook. The Aider transcript proved the failure mode is real, not hypothetical, and affects exactly the audience the rule existed for: chat-only agents (Aider, Codex CLI, OpenCode, generic terminal LLMs).

Two reinforcement spots needed:

1. **Step 2 itself.** Lead with the rule as a bolded directive — *"Hard rule — ask one question at a time. Never dump the full list."* Then name the failure mode explicitly (the wall-of-text, the loss of per-question disambiguation, the survey feeling) so the agent understands *why* not just *what*. Then a numbered 5-step protocol (ask · wait · disambiguate within turn · record · move on) so the rule translates into concrete behaviour. Then explicitly distinguish structured-picker hosts from chat-only hosts so neither misreads the instruction.
2. **The top of Part 2.** A short callout reminds any agent that lands directly on the interview text (e.g. via the new offset-read Template Index workflow — they jump to Part 2 first) to honour the Step 2 rule. The Index workflow makes Part 2 a possible entry point, not just Part 1.

Same 17 questions, same flag set, same `bootstrap.json` schema — only the agent-facing protocol changes.
